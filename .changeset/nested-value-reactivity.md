'fetchium': patch
---

Nested values passed on their own stay current. A `t.object` or `t.record` field, and a live collection's value, are merged in place when an update changes them. A component that received only the nested value, such as a `component()` child given `token.price` as a prop (or a `React.memo` child), was handed the same wrapper after the change, so once its parent stopped re-rendering it for identical props it kept showing the old value. A merge that changes a nested value in place now drops the wrapper it was handed out through: the next read through the entity, which re-renders the parent, hands out a new one, so the child sees a new prop and re-renders. An unchanged nested value keeps its wrapper, so a change to another field of the entity does not re-render a child that holds only the nested value. Reads through a live collection's value depend on the collection, which an event or a reducer already notifies. Reads through an entity's nested values cost nothing extra; a wrapper someone kept from before the change still reads the merged data but does not re-run anything.
